# 回帰テスト

`shogi.html` は1枚のHTMLなので、テストは Playwright でページを開いて中の関数を直接叩く形にしてある。

```
node tests/repetition.mjs        [new|old] [引き継ぐ手数] [試行回数]
node tests/replay-fidelity.mjs
node tests/advisor-palace.mjs    [new|old]
node tests/palace-is-diag-only.mjs
node tests/go-stone-ownership.mjs [new|old]
```

`old` を指定する場合は、比較したい版のHTMLを `OLD_HTML` 環境変数で渡す
（例：`OLD_HTML=/path/to/old.html node tests/repetition.mjs old 48 6`）。

## case273-repetition.json

CPU同士・超高速で起きた **273手・捕獲0・成り0** の実局。
先手が49手目から最後まで、**112回連続で飛車 (7,3)⇄(7,4) を往復**し続けている。

盤は素の本将棋（`pts` は全て null、`diag` も全て null、`palace=false`）。
`banSennichite=true` / `sennichiteMode="avoid"` でも止まらないのは、相手が別の駒を
少しずつ動かすため局面が完全一致せず、局面単位の千日手回避が働かないから。

### repetition.mjs が見るもの

この棋譜どおりに指定手数まで進めてから、あとをCPUに任せて160手指させ、
**同じ駒が直前の自分の手を完全に逆戻りした連続回数**を数える。

48手目から引き継いだ結果（各6回）:

| | 旧（この問題が出た版） | 現在 |
|---|---|---|
| 先手の最大連続逆戻り 平均／最悪 | 12.8 ／ 19 | **0 ／ 0** |
| 後手の最大連続逆戻り 平均／最悪 | 7.3 ／ 14 | **0 ／ 0** |
| 160手のあいだの捕獲数 | 0 | 16.8 |
| 平均nodes | — | 23 |

120手目・200手目・272手目から引き継いでも同じ傾向。

### replay-fidelity.mjs が見るもの

同じ棋譜273手を最初から再生し、報告された最終盤と1マスも違わないこと。
着手の適用そのものが正しいかの確認。

## advisor-palace.mjs が見るもの

仕・士（斜めにしか動かない宮の駒）は「宮に引かれた斜め線の上」しか動けない。
ところが「宮かどうか」の判定は *線に接するマスがあるか* という広い条件なので、
そのままだと線の通っていない場所へ行けても打ててもしまい、そこから二度と動けなくなる。

×（交差）を含む3×3の宮を作り、全ての交点・全てのマスに士を置いて総当たりする。

| | 直す前 | 現在 |
|---|---|---|
| 線に沿っていない手 | 0 | 0 |
| 行った先で動けなくなる手 | **4** | **0** |
| 打てる点のうち打つと動けなくなる点 | **16 / 32** | **0 / 16** |
| マスに打つと動けなくなる数 | **8** | **0** |

「線に沿っていない手」は元から0。報告にあった「線以外の方向へ動いている」ように見えるのは、
線の無い場所へ打たれた駒がそこに立ち続けている結果だった。

## palace-is-diag-only.mjs が見るもの

九宮は「宮マス（斜め線）」だけで表す。盤の位置から宮を決める常駐の仕組みは持たない。

以前は `RULES.palace` というフラグがあり、「適用」「作成」を押すたびに宮マスを
全部消して標準の宮を描き直していた。そのため**手で描いた宮マスが黙って消えて**いた。

| | 直す前 | 現在 |
|---|---|---|
| 手描きの宮マス → 「作成」で盤を広げる | 2マス → **0マス** | 2マス → **2マス** |
| 手描きの宮マス → 「適用」 | 1マス → **0マス** | （プリセットは盤ごと作り直すので0で正しい） |
| シャンチー／チャンギ適用後の宮マス | 8マス | 8マス |
| 「九宮をつくる」ボタン | チェック＋適用が必要 | 押した時点で描かれる |
| 古い保存データ（`palace:true` 入り） | — | 読み込める。`RULES` には残らない |

## go-stone-ownership.mjs が見るもの

碁石は **黒＝先手の駒／白＝後手の駒** で、色そのものが持ち主を決める。
誰が打っても黒石は先手の石、白石は後手の石になる。
そのため **先手は盤上の黒石を、後手は白石を取れない**（自分の石だから）。

色と持ち主が食い違うとこの前提が崩れる。駒の種類が変わりうる経路を全部検査する。

| | 直す前 | 現在 |
|---|---|---|
| オセロで裏返された碁石 | 黒石なのに後手のもの（**食い違い**） | 白石＝後手（一致） |
| 読み（simulate）の中でも同じ | **食い違い** | 一致 |
| ランダム置換で碁石になったとき | 一致 | 一致 |
| 編集で「後手の黒石」を置く | 後手のまま（**食い違い**） | 先手に直る |
| 黒石を黒で囲む | 取れない（正しい） | 取れない（正しい） |

裏返しは**色ごと**変える（黒石が後手のものになるのではなく、白石になる）。
