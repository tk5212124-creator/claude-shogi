# 将棋アプリ 仕様書

ブラウザだけで動く多変種ボードゲームアプリ。ファイルは **`shogi.html` 1枚だけ**（ビルド不要・外部依存なし）。

公開URL: https://tk5212124-creator.github.io/claude-shogi/

---

## 1. 全体像

| 項目 | 内容 |
|---|---|
| 構成 | `shogi.html` 単体（HTML + CSS + バニラJS）。約 6,000 行 |
| 対応ゲーム | 本将棋・平安将棋・小将棋・5五将棋・中将棋・大将棋・摩訶大大将棋・大局将棋・チェス・シャンチー・チャンギ・どうぶつしょうぎ・オセロ・囲碁・はさみ将棋 |
| 駒の種類 | 約 420 種（大局将棋 208 種＋成 93 種、各変種の駒を含む） |
| 盤の大きさ | 3×3 〜 40×40（行・列を独立に指定） |
| 対局形式 | 人間 対 人間／人間 対 CPU／CPU 対 CPU |
| 公開 | GitHub Pages（`main` へ push すると自動デプロイ） |

### 設計上の絶対ルール

**人間の指し手と CPU の指し手で機構を変えない。**

- 着手は必ず `applyMoveSilent(side, move)` の1本を通る
- 合法判定は必ず `isLegalMove(move, side)` を通る
- 演出の有無・描画の間引きは「音・演出トグル」と「速度設定」だけから決まり、
  指し手の主体では分岐しない（`fxEnabled()` / `renderThrottled()`）

## 2. 盤の構造 — 2つのレイヤー

盤は **マスの層** と **交点の層** の2枚でできている。

```
board[r][c]      … マスの中に置かれた駒   （NR × NC）
ptsBoard[r][c]   … 線の交点に置かれた駒   （NR+1 × NC+1）
cellDiag[r][c]   … そのマスの斜め線属性   （NR × NC）
```

**交点 (r,c) は マス (r,c) の左上の角。** つまりマスの中心と交点は必ず別の点になり、
両方に同時に駒が置ける。9×9 の盤なら交点は 10×10 個ある（外周の線にも駒が乗る）。

盤の広さはレイヤーごとに `LR(b)` / `LC(b)` で見る。

### 2層のあいだのルール

| 状況 | 挙動 |
|---|---|
| 取り合い | **できない**（別の点にいるので重ならない） |
| 縦横の進路 | **塞がない**（通り道に相手レイヤーの点が来ない） |
| 斜めの進路 | **塞ぐ**（通り道にちょうど相手レイヤーの点が来る） |
| 九宮の交差マス(×) | 斜め線がマスの中心で交わる＝**2層の共有点**。両方が置け、そこでは取り合える。層を行き来できない置き方でもここへは入れる（§2.2） |
| 囲みで取られる | 囲めるのは碁石だけ。取られる駒は種類を問わない（§2.4） |
| 斜めに飛び越えて動く駒 | 跳び越える途中の**相手レイヤーの駒も取れる**（馬・象・桂馬型） |

斜めの通り道の座標:

```
マス(r,c) から斜め(dr,dc) へ  →  通る交点は (r + max(0,dr), c + max(0,dc))
交点(r,c) から斜め(dr,dc) へ  →  通るマスは (r + min(0,dr), c + min(0,dc))
```

### 2.2 層をまたぐ移動

マスの中心と交点は「斜め半歩」ずれているので、**斜めに動ける駒だけ**が層を行き来できる
（歩のように斜めへ進めない駒は行き来できない）。角行のように斜めへ走る駒は、
その斜め方向にある交点にもマスにも交互に進める。

| 置き方 | 層をまたげる場所 |
|---|---|
| `free` | **交差宮マス(×)の中に居るときだけ**（そこからは走って行き来できる） |
| `freeMove` | いつでも |
| その他（`auto`／`crossCap`／`point`／`cell`） | **交点の駒が交差宮マス(×)へ出入りするときだけ**（下記） |

**交差宮マス(×)は「マスであり交点でもある共有点」で、その中心はマスの層に持つ。**
だから ×に立てるのはマスの層に居る駒だけで、層を行き来できない置き方でも
**交点の駒だけ**は、そこへ半歩ななめで出入りできる。

| 向き | 通るか |
|---|---|
| 交点の駒 → ×のマス | 入れる（半歩ななめの隣＝×の四隅の交点からだけ。走って遠くの×へは行けない） |
| ×の中の**交点の駒** → 交点 | 戻れる（その×の四隅の交点だけ）。チャンギの漢・楚・士は自分の動きに斜めが無いので、宮の斜め線に沿う半歩として別に足す（足さないと×に入ったきり動けなくなる） |
| ×の中の**交点の駒** → ふつうのマス | **行けない**（交点か他の×にしか行けない） |
| ×の中の**マスの駒** → 交点 | **行けない** |
| ふつうのマスの駒 → 交点 | **行けない**（`free` でも ×を経由しないと出られない） |

「交点の駒」かどうかは `goesOnPoint(t)` で決める（`auto` は囲碁・シャンチー・チャンギの駒、
`point` はすべての駒、`cell` はどれも当てはまらない）。

| 駒 | ×へ入れるか |
|---|---|
| 斜めに動ける交点の駒（仕(シャンチー)など） | 入れる |
| チャンギの漢・楚・士 | 入れる（自分の動きに斜めは無いが、宮の斜め線に沿って半歩進む） |
| 斜めに動けない交点の駒（帥(シャンチー)など） | 入れない |
| マスの駒（歩兵・角行など） | 入れない（×の中に居ても交点へは出られない） |

**持ち駒も同じで、×のマスへ層をまたいで打てるのは交点の駒だけ。**
マスの駒を交点へ打つことはできない（×の四隅の交点は、ただの交点であって共有点ではない）。
`dropTargets` は本来の層の候補を `[行, 列]`、×へ層をまたぐぶんを `[行, 列, 1]` で返す
（空き・宮の制限・自殺手・二歩・行き所のない駒などの判定は、打つ層に合わせて同じものを通す）。
`isLegalMove` の打ちの検証も、**その駒が本来置かれる層**（`goesOnPoint`）から数え直して
人・CPU・可動表示で同じ答えになるようにしている。

手のデータは移動元の層を `pt`、移動先の層を `toPt` で持つ。棋譜の `◇` も
移動元は `pt`、移動先は `toPt` で出し分ける（層をまたぐ手は `◇(9行5列)→(8行5列)` のようになる）。

### 2.3 碁石の持ち主は色で決まる

**黒石＝先手の駒／白石＝後手の駒。** 誰が打ったかではなく、色そのものが持ち主を決める。
先手が白石を打てば、それは後手の石として置かれる（後手の手番が飛ぶわけではない）。
逆に後手が黒石を打てば先手の石になる。

そのため **先手は盤上の黒石を、後手は白石を取れない**（自分の石だから）。

色と持ち主が食い違うとこの前提が崩れるので、駒を作るところは `ownerOf(t,p)` を通して揃える
（打つ・成る・ランダム置換・編集・棋譜再生）。オセロで裏返るときは持ち主だけでなく
**色そのものを変える**（黒石が後手のものになるのではなく、白石になる）。

### 2.4 囲みで取られる（連結群と呼吸点）

**囲んで取れるのは碁石だけ。取られる方は碁石に限らない。**
将棋の駒でもチェスの駒でもオセロの駒でも、碁石が条件を満たせば取られる。
逆に、相手の歩や銀にどれだけ囲まれても取られない。

**上下左右でつながった「同じ側の駒」を1つの群**として扱う。
群から外へ出られる向きが1つでも残っていれば生きている（＝**呼吸点**あり）。
**呼吸点が0になった群は丸ごと同時に取られる。**

向きを塞げるのは次のどれかだけ。

| | 塞ぐもの |
|---|---|
| ① | 隣（同じ層）に**相手の碁石**がある |
| ② | 隣へ抜ける**辺**を、別の層の**相手の碁石2つ**が挟んでいる |
| ③ | 碁石をマスの中に置けるルールのときだけ、隣の**空き交点**も「そこに集まる4本の辺のうち2本以上が碁石で塞がれている」なら塞がり扱い |
| ④ | 盤の外（壁） |

②で挟むものは層によって違う。

| 辺 | 挟むもの |
|---|---|
| マス (r,c) の上辺 | 交点 (r,c) と (r,c+1) |
| マス (r,c) の下辺 | 交点 (r+1,c) と (r+1,c+1) |
| マス (r,c) の左辺 | 交点 (r,c) と (r+1,c) |
| マス (r,c) の右辺 | 交点 (r,c+1) と (r+1,c+1) |
| 交点 (R,C) の上へ | マス (R-1,C-1) と (R-1,C) |
| 交点 (R,C) の下へ | マス (R,C-1) と (R,C) |
| 交点 (R,C) の左へ | マス (R-1,C-1) と (R,C-1) |
| 交点 (R,C) の右へ | マス (R-1,C) と (R,C) |

**2つとも相手の碁石のときだけ塞がる。** 味方の碁石・普通の駒・盤の外は辺を塞がない。
これで、マスの駒は4頂点の交点に碁石を置けば取れ、交点の駒はその点を囲む4マスの碁石で取れる。

**見る順番が大事。** 各方向について

1. 辺が塞がっているか → 塞がっていればその方向は**接続も呼吸もしない**
2. 隣が同じ側 → 同じ群としてつながる
3. 隣が相手の碁石 → 呼吸点にならない
4. それ以外（空き・相手の普通の駒） → **呼吸点**

の順に見る。1を後回しにすると、塞がれた辺の向こうの味方まで同じ群になってしまい、
**4辺を碁石で囲まれた玉将が「隣の金将には呼吸点があるから」と生き残って**しまう。

**辺の塞がりは実際に置かれている碁石だけで決める**（③を除く）。
空いている交点を「塞がっている交点」と見なして別の辺の判定に使い回すことはしない。

**自殺手は打てない。** ただしその手で相手の群を取り、その結果自分の群に呼吸点が生まれるなら合法。

**囲みで取った駒は棋譜にも残る**（`取:` に並ぶ。自分の群が死んだときは `失:`）。

判定は `surroundedGroup` / `captureSurroundedNear` / `isSuicidePlacement` の1組だけで、
人の操作・打ち先の候補・CPUの読み（`simulate`）・棋譜再生がすべて同じものを使う。

群が死ぬのは呼吸点が埋まったときだけなので、着手のたびに盤全体は見ない。
**その手で新しく埋まった場所・持ち主が変わった場所とその隣**だけを見る
（空きになった場所は呼吸点が増えるだけで、群が死ぬことはない）。
そのため、**古い版で作られた保存データを読み込んだときは、その時点では取り残しがそのまま残る**。
その辺りに手が触れた時点で取られる。新しく始めた対局では最初から正しく取られる。

### 2.5 駒の置き方（盤の設定「駒の置き方」）

| 設定 | 交点に置かれる駒 | マスに置かれる駒 |
|---|---|---|
| `auto`（既定） | 囲碁・シャンチー・チャンギの駒 | それ以外 |
| `crossCap` | `auto` と同じ。さらに**斜めの通り道にいる相手レイヤーの駒を取れる** | それ以外 |
| `cell` | なし（交点レイヤーを使わない） | すべて |
| `point` | すべて | なし |
| `free` | 自由（編集で選んだ側に置ける） | 自由 |
| `freeMove` | 自由。さらに**常時どちらの層へも進める** | 自由 |

**交点は 0〜NR・0〜NC なので、盤の端（最下段・最右列）はマスの盤には無い。**
編集まわりで座標を使うところは、必ず「置く場所」で選んでいる層を見る。
マスの盤を引くと、最下段の交点で落ちて駒を置けなくなる。

編集ツールの「プリセット配置」は、盤に並べるだけでなく
**囲碁・オセロの持ち駒も「適用」と同じ数だけ用意する**（`PRESET_HAND`）。
数は `setupGo` / `setupOthello` と1か所で共有する。
足りないぶんだけ足すので、2回押しても増えすぎない。囲碁は盤に初期配置が無いので、
盤の駒が0枚でも持ち駒は付く。

編集モードでは「置く場所」（マスの中／線の交点）を明示的に選ぶ。
`auto` のときは種類に合わない側には置けず、駒一覧もその側に置ける駒だけに絞られる。
**ただし ×（交差宮マス）は「マスであり交点でもある」ので、交点の駒はその中にも置ける。**
`layerAllows(t,isPt,r,c)` に場所を渡すとそのマスが×かどうかまで見る。場所を渡さないとき
（駒一覧の絞り込み）は、盤に×が1つでもあれば候補に出し、実際に置けるかは置くときに見る。
囲みのルール判定（`goStoneInCell`）はこの例外を使わない。盤に×が1つあるかどうかではなく、
「碁石をマスの中に置けるルールか」だけを見るため。

**`crossCap`（斜めの通り道の駒を取れる）**
ふつうは、斜めに動くと通り道にちょうど相手レイヤーの点が来るので、そこに駒があると
**塞がれて通れない**（`diagBlocked`）。`crossCap` ではその駒が相手のものなら
**取って通り抜けられる**（自分の駒なら今までどおり塞がれる）。
「マスの駒から見た交点の駒」も「交点の駒から見たマスの駒」も同じように取れる。
取った駒は共有点の取りや飛び越えの取りと同じ `xcaps` として棋譜に残る（`crossJumpPoints` が
`jump` の駒に加えて、45度の斜め1歩・走りの通り道も返すようになる）。

`syncLayers()` は ×（共有点）に居る駒を層のあいだで動かさない。
そうしないと、置き方を切り替えたときに ×へ入れた交点の駒が押し出されてしまう。

## 3. 九宮（宮マス）

九宮は**マスの斜め線属性だけ**で表現する。各マスは `'l'`(＼) / `'r'`(／) / `'x'`(交差) / `null` のいずれかを持つ。
**盤の位置から宮を決める仕組みは持たない**（二重管理になり、手で描いた宮マスと食い違うため）。

- 編集メニューの「宮マス変更」で1マスずつ、複数選択バーの「宮マス変更」でまとめて設定
- 盤の設定の「**九宮をつくる**」は、押した時点で標準の位置（列数が奇数なら 3×3、偶数なら 2×2）に
  宮マスを描くだけのボタン。設定として残らないので、**盤の大きさを変えても宮マスは消えない**
- 「宮マスを消す」で全部消える
- シャンチー・チャンギのプリセットは、配置と一緒に宮マスも描く

### 宮の判定（**盤の位置では判定しない**）

| 対象 | 宮かどうかの判定 |
|---|---|
| マス (r,c) | そのマスが斜め線を持つ、または交差マス(×)の縦横1マス隣 |
| 交点 (R,C) | その交点を角に持つ4マスのどれかが斜め線を持つ（交差マス自身も共有点として含む） |

宮が盤のどこにあっても同じように動ける。

### 宮から出られない駒（帥・將・仕・士・漢・楚）

九宮のチェックの有無に関係なく、常に宮の外へは出られない（宮が無ければ動けない）。
**持ち駒から宮の外へ打つこともできない。**
ルール設定の「九宮の駒が宮マスの外にも出られるようにする」で解除できる。

**交点に居るとき**

- 帥・將 … 宮の点どうしを縦横1つ
- 仕・士 … その交点から**実際に伸びている斜め線の向き**にだけ
- 漢・楚 … 縦横＋線に沿った斜め

**マスの中に居るとき**

- 仕・士 … そのマスに引かれた斜め線の向きにだけ
- 帥・漢 … 宮のマスの中、または交差宮マスの縦横1マス隣まで

### 仕・士は線の上にしか立てない

仕・士は線の上しか動けないので、**線が通っていない場所へは行けず、打つこともできない**
（そこへ置くと二度と動けなくなるため）。上の「宮かどうか」の判定は *線に接するマスがあるか*
という広い条件なので、この駒にだけは「実際に線が通っているか」という狭い条件を使う。
帥・將は縦横に動くので、こちらは従来どおり宮の点であれば立てる。

## 4. ルール設定

### 共通

| 設定 | 既定 | 内容 |
|---|---|---|
| 持ち駒を使う | ON | 取った駒を打てる。**royal（王・玉・帥など）も他の駒と同じ**で、取れば持ち駒になり打てる |
| 取った駒は成ったまま | OFF | 成駒のまま持ち駒にする |
| 二歩を禁止 | ON | |
| 千日手の扱い | 千日手を避ける | 避ける／同一局面4回で引き分け／シャンチー式／制限なし |
| パス（着手放棄） | OFF | 盤下に「⏭ パス」。CPU も同じ手として使う。**双方が続けてパスすると終局**（間に着手が入れば数え直し）。取り切るルールなら盤上の駒数の多い方の勝ち、それ以外は引き分け |
| 格なしの駒を一般駒として扱う | ON | 範囲攻撃の対象になる |
| ランダム置換・ランダム成りの候補に特殊駒を含める | ON | 囲碁石・オセロ駒・はさみ駒。他は常に候補 |
| 成り条件をもう一度満たすと更に成れる | OFF | 満たした条件の数だけ連続で成る |
| 成り先のない駒はランダムな駒に変化 | OFF | royal は royal へしか成らない |
| 取り切るまで戦う | OFF | 王の有無に関係なく全滅で決着 |
| 相手の点数がなくなるまで戦う | OFF | 相手の盤上の点数が0で決着（王の有無では決着しない） |
| 点数だけで勝負する | OFF | 勝敗を盤上の点数で決める（終わり方は変えない） |

千日手の局面キーには**交点レイヤーも含む**。

### 成る条件（3つとも外すと成りが無くなる）

敵陣に入ったら／敵陣の一番奥に着いたら／敵駒を取ったら

### 王手の判定

`checkInfo(p)` は **「どの層のどの royal に掛かっているか」** を `行_列_層`（層は `c`=マス／`p`=交点）で返す。

層を区別しないと、マスと交点の同じ座標に別々の royal が居るとき、**片方の王手で両方が赤く光る**。
また、層をまたぐ手（×へ入る手）は**行き先の層**の royal を狙うものとして数える
（移動元の層で数えると、居もしない駒への王手になる）。

`checkPoints`（4人チェスの王手加点）の「同時に王手を掛けた数」もこの数え方に従う。

### 勝敗の一般則

**盤上から味方の royal 駒（王・玉・帥・漢・ライオンなど）が居なくなった側の負け。**
取られた・オセロで裏返された・碁石に囲まれた・はさまれた・焼かれた…どの理由でも同じ扱いで、
着手のたびに両者を確認する（`hasRoyalOnBoard`）。**数えるのは盤上だけ**なので、
royal を取って持ち駒にしても、取られた側の盤上に別の royal が残っていれば対局は続く。
**「王を取ったら終わり」＝「盤上から royal がぜんぶ消えたら終わり」**なので、
王が複数居るゲーム（大局将棋の玉将＋太子など）では1枚取っただけでは終わらない。
1枚目で終わらせたいときは下の `endOnRoyalCapture` を使う。
「相手の駒を全て取る（取り切る）まで戦う」ルールのときだけ別で、王の有無では決着しない。

### 引き分け（持将棋）

どこにも動けなくなったら（既定ON）／双方の王が敵陣に入ったら（既定OFF）。

決め方はルール設定で選ぶ（`jishogiMode`）。`points`＝点数計算で勝敗を決める（既定）／`draw`＝点数を見ずに引き分けにする。

点数の内訳:

| 内訳 | 設定 | 中身 |
|---|---|---|
| 盤上の駒価 | 常時 | 盤上の自分の駒の駒価の合計（royal は除く） |
| 囲碁の領域点 | 常時 | 自分の石だけが接している空き交点の数（碁石が盤に無ければ0） |
| 取った駒の駒価 | `capturedPoints`（既定ON） | 持ち駒の駒価の合計。王を取った分（20点）もここに入る |
| 王手の点 | `checkPoints`（既定OFF） | 王手1回につき下の表の点（4人チェス式） |

24点・31点・500手のルールは「双方の王が敵陣に入ったら持将棋」がONで、実際にその形になったときだけ使う。
それ以外は単純に点数の多い方の勝ち。

**点数はいつも画面に出る**（`points` のとき、および下の「点数だけで勝負する」のとき）。
持ち駒の欄の右に `27点` のように出す。

### 終わり方の設定（`captureAll` / `endByScore`・どちらも既定OFF）

「相手の駒を全て取る（取り切る）まで戦う」（`captureAll`）と
「相手の点数がなくなるまで戦う」（`endByScore`）の2つのチェックで**終わり方**を選ぶ。

| `captureAll` | `endByScore` | 終わり方 |
|---|---|---|
| OFF | OFF | 王が盤上から居なくなったら（既定） |
| ON | OFF | 全滅まで（王を取っても終わらない） |
| OFF | ON | **相手の盤上の点数が0になったら**（王を取っても終わらない） |
| ON | ON | 先に満たした方 |

`royalDecides()`＝`!captureAll && !endByScore`、`scoreZeroEnds()`＝`endByScore`。
点数は **盤上の駒価＋囲碁の領域点**（`calcPositionScore`）で数える。
取った駒の点は減らないので0にできず、この数え方には入れない。

### 王を1枚でも取った時点で終わる（`endOnRoyalCapture`・既定OFF）

上の2つとは**独立した終わり方**で、王が複数居ても**1枚目を取った時点**で決着する。
どれか1つでも先に満たした条件でそこで終わる（`captureAll` / `endByScore` がONでも効く）。

判定は**盤上の royal の枚数**（`countRoyalsOnBoard`）を着手の前後で比べるだけなので、
取り・囲み・オセロの裏返し・火鬼の焼き…どの理由で減っても同じ扱いになる。
自分の royal が減ったときは相手の勝ち。勝ち負けは `endByRoyal()` を通すので、
`scoreOnly` がONなら**どちらが王を取ったかに関係なく点数の多い方の勝ち**になる。

CPUの読み（`simulate`）も同じ条件で、`king`（この手で勝ち）を
「相手の royal がぜんぶ消えた」に加えて「1枚でも取った」でも立てる。
`anyRoyalEnds()` がその切り替え。

### 点数だけで勝負する（`scoreOnly`・既定OFF）

こちらは**勝ち負けの決め方**の設定で、終わり方は変えない。
決着したとき、**どちらが王を取ったかに関係なく点数の多い方の勝ち**（同点なら引き分け）。
王が居なくなっての終局は `endByRoyal()` を通し、そこで点数を見る。
持将棋（動けなくなった等）になったときも、`scoreOnly` なら単純に点数の多い方の勝ち。

`scoreOnly` がONのときは、画面に出る点数も盤上の点数（緑色）になる。

古い保存の読み替え:

| 古い保存 | 読み替え先 |
|---|---|
| `jishogiMode:'zero'` | `points` ＋ `endByScore` ＋ `scoreOnly` |
| `captureAll`＋`scoreOnly` で `endByScore` が無い | `endByScore` もON（終わり方が分かれる前の版） |

**王手の点（4人チェス式）。** royal が複数あると1手で同時に王手を掛けられる。

| 1手で同時に王手を掛けた royal の数 | クイーン系の駒 | それ以外 |
|---|---|---|
| 1つ | 1点 | 1点 |
| 2つ（ダブルチェック） | 1点 | 5点 |
| 3つ以上（トリプルチェック） | 5点 | 20点 |

「クイーン系」は8方向すべてへ無条件で走る駒（チェスのクイーン・奔王など）。
砲・包のように走るのに条件が要る駒は含まない。判定するのは**着地した駒**（成ったら成った後の駒）。

### シャンチー

- 王不見王（帥と将を同じ筋で相対させる手は指せない。全ての手が相対になる場合は負け）
- 九宮の駒が宮マスの外にも出られるようにする

### チャンギ

- ビッチャングン（漢・楚が相対したら、相手は解消する手しか指せない。解消できなければ引き分け）
- 馬・象の並び（標準／馬が内側／左だけ入替／右だけ入替）

## 対局を始める前の画面（ルールと盤の設定）

新しい対局になったとき、盤の上に **「この設定で対局します」** の画面を出す（オンライン対戦以外でも）。
中身は `ruleSummaryHTML()`：ゲーム名・盤の大きさと敵陣・駒の置き方・先手・あなた／相手（手動・CPU・オンラインの相手）・
終わり方・勝ち負けの決め方・成る条件・千日手・持将棋、それに「あり」のルールの一覧（「なし」は畳んである）。

- 出すとき：**1手も指していないときに ▶ 開始 を押したとき**。準備中（プリセット・大きさ・配置の編集など）には出さない
  （出しっぱなしだと盤の設定ボタンや盤に被っていじれないため）。盤をタップして手動で指し始めたときも出さない。
  **オンラインでは相手とつながったらすぐ**出す（作った側・入った側とも。▶ 開始 は使わないため）。
  対局の途中の変更が許可されて新しい対局になったときも、入った側に出す。
- 出ている間に設定が変わったら中身を作り直す（`refreshStartCard`）。
- 消えるとき：「この設定で始める」（ここで対局が始まる）・1手目を指したとき・編集を始めたとき。
- ゲーム名は `gameName`（保存データにも入る）。盤の大きさを変えると「（7×7に変更）」、編集すると「（編集あり）」が付く。
- プリセットを適用したあとに自動で切り替わるルールも反映するよう、中身は処理が終わってから作る。

## 7. 保存・読み込み

| ボタン | 内容 |
|---|---|
| ルール・初期配置をコピー | 盤・交点・持ち駒・ルール・斜め線（**指し手は含まない**） |
| 棋譜（ルール・初期配置含む）をコピー | 上記＋指し手＋起点＋読みやすいテキスト |

貼り付け欄に貼って「読み込み」すると復元する。

- **ルール・初期配置**を貼る → そのルール・その配置から始められる
- **棋譜**を貼る → その対局の続きから再開できる（リプレイも見られる）

デバッグ情報まるごと貼っても、中の JSON 部分を自動で取り出して読み込む。

### 棋譜の表記

- 交点の手には **◇** が付く（`◇(3行8列)`）。交点は 0〜NR なので 9×9 盤でも 10 が出る
- 層をまたいで着地したときは、着地先の駒を `tg` として取るので、共有点の取り（`xcaps`）には数えない（二重取りの防止）
- パスは `▲パス（着手放棄）`
- 成りは `成→（成った駒）`

**取りは5通りあり、どれも `取:` にまとめて出す。** 盤から消えた駒は必ずどれかに入る。

| 記録 | どんな取りか |
|---|---|
| `cap` | 移動先に居た駒 |
| `capsCodes` | **移動の途中で取った駒**（獅子型の2枚取り・居喰い）。座標は `caps` |
| `xcapCodes` | 相手レイヤーの駒（交差宮マスの共有点・斜めの飛び越え）。座標は `xcaps` |
| `enclCap` | 囲みで取った駒 |
| `enclLost` | 自分の手で自分の群が死んだぶん（こちらは `失:` で出す） |

駒の種類は**盤を書き換える前に**拾う。着手記録より後だと、もう駒が消えていて取れない。
`tests/kifu-captures.mjs` が、1手ごとに「持ち駒に入った数」と「棋譜が書いた数」を
突き合わせて、書き漏らしが出ないことを見張っている。

## オンライン対戦（ログイン不要・招待URL）

「🌐 オンライン対戦」→「部屋を作る」で合言葉と招待URLが出る。相手がそのURLを開くか、
合言葉を入れて「入る」を押すとつながる。アカウントもサーバーも要らない。
合言葉・招待URLはそれぞれ「コピー」ボタンで写せる。入る側は「貼り付け」ボタンで貼れて、
合言葉だけでも、招待URLや共有メッセージまるごとでも、中から合言葉を取り出して入る。

**合言葉は6けたの数字。** 英字まじり（`g65n9p`）だと 9 と q などを見間違えて
「部屋が見つかりません」になったので、数字だけにした。全角数字で入れても読める。

**つながりにくいときの粘り。**
- 入る側：部屋がまだ無くても、すぐにはあきらめず数秒おきに探し直す（最大15回）。
  先に「入る」を押してしまっても、あとから部屋ができれば入れる。
  見つからなかったときは、入れた合言葉をそのまま見せて止まる（打ち間違いに気づけるように）。
- 作った側：携帯で別の画面に切り替えるなどして仲介サーバーから外れたら、
  同じ合言葉のまま自分でつなぎ直す（画面に戻ったときにも確かめる）。
- **指した手が届かないことへの備え。** 携帯で画面が消えたり別の画面に切り替えたりすると、
  通信が知らせもなく止まることがある（指したのに相手に反映されない、が起きた）。
  - 手には「届いた」の返事（`ack`）をもらう。来なければ2.5秒ごとに送り直す。同じ手が2度届いても1度しか反映しない。
  - 3秒ごとに手数つきの合図（`ping`）を送り合う。10秒何も届かなければ切れたとみなし、
    入った側がつなぎ直す（作った側が画面に戻るまで待ち続ける）。つなぎ直す間は指せない。
  - つなぎ直したら、届いていなかった自分の手を挨拶（`hello`）に添えて渡し、作った側はそれを反映してから盤を送る。
  - 合図には手数と**盤の指紋**（作った側の向きにそろえた盤・交点・持ち駒・手番から作る値）を添える。
    どちらかが2回続けて食い違ったら、作った側の盤を送り直してそろえる（指した手が通らなくなる前に直す）。
    画面に戻ってきたときはすぐ確かめる。
  - 盤を送り直すたびに番号（`epoch`）を付け、それより前の盤で指された手は捨てる。盤を受け取った側は返事待ちの手も捨てる
    （前は、通らなかった手を送り直し続けて「食い違い→送り直し」を繰り返していた）。
  - 食い違ったときは、両方の盤（と通らなかった手）をデバッグ情報の「オンライン：盤が食い違った記録」に残す。
- **同じ携帯の2つのブラウザで試すと、裏に回った側を iPhone が止めるのでつながらないことがある。**
  試すときは端末を2台使う。

**しくみ。** ブラウザ同士を WebRTC で直接つなぐ。最初につなぐときの仲介だけ
PeerJS の公開サーバー（無料・動作保証なし）を使う。通信用の部品（peerjs）は
「部屋を作る／入る」を押したときに初めて読み込むので、普段の起動は重くならない。

- **部屋を作った人（ホスト）の盤・持ち駒・ルールをそのまま送る。** 相手の画面では、
  盤を180°回して持ち主を入れ替えた形で持つ（先後入替と同じ変換）。
  どちらの画面でも自分が「あなた」（下）になる。碁石は色が持ち主を決めるので、
  入れ替えるときは色も入れ替える（相手の画面では自分の石が黒に見える）。
  打つ碁石だけでなく、**ランダムに成った先が碁石のとき（成り先 `promoTo`）も入れ替える**。
  入れ替えないと、どちらの画面でも「相手の石」になって盤がずれる。
- **送るのは棋譜1手ぶんの記録。** 自分の手は `recordKifu` を通るところで送る。
  受け取った側は向きを直してから、人やCPUの手と同じ `isLegalMove` と
  `applyMoveSilent` に通す（オンライン用に別の動かし方を作らない）。
  合法でない手は盤に反映しない。チェスのキャスリング・アンパッサンは
  人の手と同じ `doCastling` / `doEnPassant` を通す。
- **手数（ply）を添えて送る。** 食い違ったら、ホストが盤をまるごと送り直して揃える。
  千日手・王手点などの記録もそこから数え直す。
- **ホストだけが変えられるもの**：プリセット・盤の大きさ・敵陣・駒の置き方・九宮・ルール・先後入替・
  初期配置に戻す・指し直し・読み込み・盤の編集。ゲストの画面ではこれらを**押せなくする**
  （`onlineSyncLocks`。前は「作成」「九宮をつくる」「駒の置き方」がゲストでも押せてしまっていた）。
- **相手が入ったあとでも変えてよい**（部屋を作る前に全部決めておく必要は無い）。
  - **1手も指す前・対局が終わったあと**：変えるとその場で相手に送り直す。
  - **対局の途中**：勝手に変えると不公平なので、**相手の許可が要る**。ホストが変え終えると
    （ボタンを押したとき・編集を終えたとき・ルール画面を閉じたとき）、ゲストに「○○の相談」の窓が出る。
    ゲストの盤には変えたあとの形を見せ、ルールと盤の設定の一覧も出す。
    「許可する」でそのまま続け、「断る」とホストは変える前の局面（棋譜も）に戻して送り直す。
    返事を待つ間はどちらも指せない。何も変えずに閉じたときは相談しない。
  - 変える前の局面は `onlineBeginChange` で覚え、`onlineCommitChange` で相談するか送るかを決める。
- **ホストが盤を編集している間・ルール画面を開いている間は、相手は指せない**
  （`{t:'hold'}` を送り、相手の画面に「部屋を作った人が盤を編集中です」と出す）。
  編集を終える／ルール画面を閉じると盤ごと送り直して解ける。
  つながった直後も、ホストの盤が届くまでは同じく指せない（古い盤のまま指すのを防ぐ）。
- **対局中は使えないもの**：待った・1手進める・開始／一時停止・相手側のCPU。
- **自分の手番をCPUに任せるか**はルール「オンライン対戦で、自分の手番をCPUに指させてよい」で決める（既定はOFF）。
  ONなら「あなた：CPU」にでき、CPUの手も人の手と同じ道を通って相手に届く。相手には「相手は自分の手番をCPUに指させています」と出る。
  途中でOFFにすると（相手の許可のうえで）CPUは止まる。
- **投了**は相手にも伝わる。ページを閉じると相手に「退出」を知らせる。
  同じ招待URLを開き直せば、ホストが盤を送り直して再開できる。

**できないこと・弱いところ。**
- 知らない人との自動マッチングは無い（待っている人の一覧を置く場所が要る。Firebase や自前サーバーが必要）。
- 仲介サーバーが止まっていると部屋を作れない。回線の組み合わせによっては直接つながらないことがある
  （中継サーバー＝TURN は用意していない）。
- 2人の間の通信なので、改造したブラウザでの不正は完全には防げない（不正な手を盤に反映しないところまで）。

あわせて、チェスで8×8の盤に合っていなかった3か所を直した（9×9 を前提にした数字が残っていた）。
ポーンの最初の2マス進み（`LR(b)-3` → `LR(b)-2`）、キング側のキャスリング（ルークの列 `8` → `NC-1`）、
後手ポーンの昇格の段（`8` → `NR-1`）。

## 8. CPU

αβ探索。評価は駒の価値＋前進ボーナス＋敵玉への接近ボーナス。

**探索と実ゲームで勝敗判定を揃える。** 探索側（`simulate`）が royal を取った手を
「即勝ち」とみなすのは、**その手で相手の royal が盤上から全て消えたときだけ**
（`anyRoyalIn`）。royal が複数ある盤では1枚取っても勝ちにしない。
「取り切るまで戦う」ルールでは royal では決着しない。実ゲームの
`hasRoyalOnBoard` と同じ考え方を使う。

**評価にランダム加点はしない。** 完全に同点の手が複数あるときだけ、その中から
等確率で選ぶ（`ties`）。

**手の並べ替えは行き先のレイヤーを見る。** 交点の手でもマス側だけを見て
0点にしてしまわないようにし、royal を取る手・成りを優先する。

**速度は「深さ」ではなく「1手にかける時間」で決める。** 同じ深さでも盤や局面で必要な
計算量はまるで違うので、深さを固定すると軽い盤では余力を捨て、重い盤では待たされる。
持ち時間で止めればどのゲームでも操作感が揃い、軽い局面ほど自然に深く読む。

| 速度 | 1手の持ち時間 | 本将棋で届く深さ | 以前の1手の時間 |
|---|---|---|---|
| 熟考 | 2 秒 | 5前後 | 2.3 秒（深さ4） |
| 標準 | 0.4 秒 | 4〜5 | 0.7 秒（深さ3） |
| 高速 | 0.08 秒 | 3〜4 | 0.05 秒（深さ2） |
| 超高速 | 深さ1で固定（即答が身上） | 1 | 0.005 秒 |

盤による差も無くなった。以前の標準は オセロ 0.015 秒／シャンチー 3.9 秒／大局将棋 8.8 秒
とばらついていたが、いまはどれも 0.4 秒以内（大盤は深さを絞るのでそれ以下）。

**意図的な待ち時間は入れない**（手と手の間隔は 0）。演出ONのときだけ、演出が見える
最小の 170ms をあける。

反復深化：深さ1から順に読み進め、**前の深さの最善手を先頭に並べ替えて**
（枝刈りが効くように）次の深さへ進む。持ち時間を超えたらその深さは丸ごと捨て、
**読み切れた一番深い結論**を採用する。時計は256節点に1回だけ見る。
2秒で届く深さの目安：どうぶつ・オセロ7、5五将棋・本将棋5、チェス4〜5。

盤が大きいほど浅くする。熟考は持ち時間が長いので絞りすぎない（18路以上は深さ2、
13路以上は深さ3、候補64手まで）。それ以外は画面が固まらないよう従来どおり浅くする
（18路以上は深さ1、13路以上は深さ2、候補18手まで）。
着手は必ず人間と同じ `isLegalMove` を通す。

### 8.1 探索を速くしている仕組み

**合法手も評価値も変えない。**「どの順に読むか」「同じ計算を二度しないか」だけを変えてある。

| 仕組み | 内容 |
|---|---|
| 手の並べ替え | 探索の内側でも並べ替える。取りの価値（royal＞駒価値）＋成り＋獅子の途中取り、置換表の最善手、killer（各plyに2手）、counter（直前手への返し手）、history（cutoffを起こした手にdepth²） |
| 置換表 | 局面を53bitのキーにして結果を記憶。合流した局面を読み直さない。乱数表は持たず `mix32()` で座標と駒種から生成。**確定値、または今の窓だけで結論が出る境界値のときだけ**使う（αβの窓は動かさない）。詰み点は残り深さを含むので保存しない。残り1手の節点では使わない（ハッシュ代の方が高い）。盤の大きさやルールは編集で変わりうるので1手ごとに捨てる |
| ルートの窓 | 候補ごとに全窓で読み直すのをやめ、今の最善のわずかに下を下限にする。同点以上の手は正確な値が返るので、**選ばれる手も同点時の等確率選択も変わらない** |
| 盤のコピー | 駒オブジェクトは書き換えられないので、読みの中では行の配列だけ複製する |
| 評価 | 玉の位置を1周でまとめて拾い、盤の走査を3周から2周に減らした |
| 囲碁の囲み取り | 碁石が1つも無い盤では全面走査をしない（碁石は打つ以外で増えないので親から引き継ぐ） |

いずれも**局面から導ける情報だけ**で分岐しており、呼び出し元が人かCPUかでは分岐しない。

同一局面・深さ4の探索時間（本将棋 301ms → 現在、以前は 8.7 秒）。
無改造の探索を正解として、CPUの選ぶ手が常に最善値と一致することを確認している。

## 9. 演出

**演出を出すかは「音・演出：ON」だけで決まる。速度では勝手に切らない。**
超高速でも演出ONなら毎手描画し、演出が見えるよう1手あたり最小170msの間隔をあける
（演出OFFの超高速は従来どおり0ms・数手ごとにまとめて描画）。

- **駒を取る** … 斬線3本（会心5本＋金の一閃）／ヒット閃光／衝撃波リング／木片／粒子／ダメージ数値／盤の揺れ＋ヒットストップ。会心は画面ごと振動＋2度焚きフラッシュ＋集中線
- **成る** … 画面全体の金フラッシュ＋集中線＋衝撃波＋振動、放射光、光柱、金のリング3重、輝きの粒
- **移動** … 残像と着地の土煙
- **王手** … 赤いビネットと集中線
- **オセロ** … 1枚ずつめくれてリングが弾け、4枚以上で「○枚返し！」
- **勝敗** … 画面フラッシュ＋振動、紙吹雪120枚、勝利は星も舞う

効果音は `sfx/` の mp3 を鳴らす。`SFX.play(名前)` の1か所だけが音を鳴らす。
**割り当ての無い場面は Web Audio の合成音にそのまま落ちる**ので、ファイルが読めなくても無音にならない。

| 場面 | 既定（題名） |
|---|---|
| 倒す（シャッキーン／ザシュッ／デュクシ） | `shakeen`（シャキーン）／`shakin-short`（短いシャキン）／`punch`（パンチ） |
| 駒を動かす／持ち駒を打つ | `pachi.wav` / `pachi-drop.wav`（もとの合成音を書き出したもの） |
| 会心の一撃 | `punch-heavy`（重いパンチ） |
| 火鬼が焼く | `fire`（火炎攻撃） |
| 王手 | `thunder`（雷魔法） |
| 成る | `status-up-1`（ステータス上昇魔法1）＋ `levelup.wav`（前のレベルアップ音）を**同時に鳴らす** |
| オセロの裏返し | `whip`（鞭。ピシッと返す） |
| 勝ち／負け／引き分け | `win.wav` / `lose.wav` / `draw.wav`（もとの合成音を書き出したもの） |

場面の無い音（魔法陣展開・高速移動・鎧の騎士が歩く／走る・壁を破壊する・重い殴りなど）も
試聴の一覧には入れてあり、画面から好きな場面に差せる。
題名が分からない5本（`hit-short` / `hit-dry` / `hit-mid` / `boom-1` / `boom-2`）は「未確認」と表示する。

**ファイル名は中身の題名どおりにしてある。** 最初は題名が分からず、鳴らして測った性格から
仮の名前（chime-1 など）を付けていたが、聞いて分かった中身と食い違っていた
（例：澄んだ音1 と呼んでいたものは実はシャキーン、ファンファーレは壁を破壊する音）。
名前を変えたので、前に選んで保存した割り当ては `SE_RENAMED` で新しい名前に読み替える。

**駒を置く「パチ」は、もとの合成音をファイルに書き出して鳴らす。** パチは 0.05 秒より短い音で、
もらったファイル（いちばん短いもので 0.24 秒）には当てはまるものが無い。
合成のまま鳴らすと、ファイルの音は聞こえるのにパチだけ鳴らない端末があったので、
全部の効果音を同じ `<audio>` の道に揃えた。書き出しは `OfflineAudioContext` で
SFX の合成コードをそのまま描画し、山を 0.32 にそろえて 16bit WAV にしている。

成るときは以前「轟音（crit）」を重ねていたが、ステータス上昇魔法が埋もれるので重ねない。

アップロード時に日本語の題名が失われたため、題名は聞いた人に教えてもらって付けた。

音の下の行で**場面と音を選んで ▶ で試聴**でき、選び直すとその場で差し替わる。
**覚えるのは自分で選び直した場面だけ**（`localStorage['shogiSe2']`）。
全部の場面を覚えると既定を直しても古い割り当てが残り続けるため
（駒音を合成のパチに戻したのに、古い保存が勝って攻撃音のままだった）。
全場面を覚えていた古い保存 `shogiSeMap` は読み込み時に捨てる。

**緩急を付ける。** 駒音は小さく（体感 0.027）、倒す音は大きく（0.09〜0.12）。
何度も鳴るもの（王手・裏返し）は `SE_VOL` で音量を下げる。
`sfx/` のファイル名は、鳴らして測った性格（長さ・明るさ・ざらつき・立ち上がり）から付けた
便宜的なもの。中身を聴いて合わなければ画面から差し替える。

合成音はノイズで作っているので、鳴らすたびに山の高さが動く。**割れない余裕を残す**
（倒す音3種の最大は 0.63〜0.85 に収まる）。テストは3回鳴らして最悪の回で見る。

鳴らすのは BGM と同じ `<audio>`。ファイルを取りに行かずに済むので `file://` でも動く。
**鳴らすまで1バイトも読み込まない**（`new Audio()` を最初の再生時に作る）。
同じ音が重なるぶんは1つにつき最大4つまで使い回す。

合成音は `tests/defeat-sound.mjs` / `defeat-sound-shape.mjs` が見る（割り当てを外してから測る）。

**「鐘になっていないか」はスペクトルの平坦さで測る。** ゼロ交差のばらつきでは測れない
（低音を敷くとゼロ交差が低い周波数で揃うため、ざらついていても数値が下がる。実際
シャッキーンは、わざと鐘にしてある「成る」の音より低く出てしまう）。
純音が数本立っているだけなら平坦さは 0 に近く、広帯域なら大きい。
鐘だった版は 0.008 で「成る」の 0.010 を下回っていた。現在は 0.042。

**倒したときの音は3種から1つ選ぶ**（`SFX.play('defeat')`）。
毎回同じだと飽きるので、直前と同じものは選ばない（`pickDefeat`）。

| 名前 | 音 | 作り |
|---|---|---|
| `shakeen` | シャッキーン！ | 抜刀の「シャッ」＋金属の非整数倍音の「キーン」＋斬った手応えの低音 |
| `zashu` | ザシュッ！ | ざらついた一閃。残響を残さず切り上げ、下に「ドスッ」を敷く |
| `dukushi` | デュクシ！ | 「デュ」＝低く重い打撃、「クシ」＝短いノイズ |

`'capture'`（旧名）も同じ3種に振り分ける。会心のときはここに `crit`（轟音）を 90ms 後に重ねる。

**倒す音を正弦波の倍音で作ってはいけない。** 倍音がきれいに整列して鐘（ピロン）になる。
一度 2637 / 3951 / 5274 Hz（E7・B7・E8）で刃鳴りを組んでしまい、実際に鐘の音になった。
金属の鳴りは `noiseRing()`（ノイズ→鋭いバンドパス）で作り、
周波数は叩いた金属の棒の比（1 : 2.76 : 5.40 : 8.93）でわざとずらす。

**低音で下を支える。** 高い刃鳴りだけだと軽い音に聞こえる。
以前は `slash`（高い金属音）の直後に `capture`（低音の塊）を重ねていて、
その低音を外したら「ピロン」としか聞こえなくなった。3種とも低音の手応えを持たせてある。

数字で見ると（`tests/defeat-sound-shape.mjs` が波形をそのまま測る）

| | 最大 | 体感の大きさ | ノイズらしさ |
|---|---|---|---|
| 倒す音3種 | 0.61〜0.82 | 0.094〜0.115 | 0.96〜4.85 |
| `move`（駒を動かす音） | 0.16 | 0.012 | 0.67 |
| `crit`（会心の轟音） | 0.84 | 0.155 | 2.19 |

- **最大**が 1.0 を超えると割れる
- **体感の大きさ**（最初の0.3秒の実効値）が `move` の5倍を切ると、駒音に紛れて聞こえない
- **ノイズらしさ**（ゼロ交差の間隔のばらつき）が `move` 並みに低いと、純音＝鐘になっている

**音の起こし方（iOS 対策）**
iOS/iPadOS は「指で触ったその瞬間」にしか音を鳴らし始められず、触ったあとも
`AudioContext` が `suspended` のまま残ることがある。そのため

- 解除は `pointerdown` / `touchend` / `click` / `keydown` を **capture で**聞く
  （途中で `stopPropagation()` されても拾える）。`running` になるまで外さない
- タブに戻ったときも `visibilitychange` で起こし直す
- iOS のときだけ、無音の wav を1つループ再生して音声セッションを掴む（`holdSession`）。
  こうすると効果音が消音スイッチに引きずられず、BGM と同じ扱いになる
- 「音・演出」をONにすると確認の音が鳴る。鳴らせない状態なら
  `SFX.state`（`suspended` など）を画面に出す。黙って無音にしない

**画面の揺れは `#page` に掛ける。** `body` そのものを transform すると
`body::before`（背景）が body 基準の巨大な要素になり、文書の横幅が広がって
画面が縮んで表示される。`html`/`body` には `overflow-x:clip` を付けてある。

🔁 **全曲**（1曲終わったら次へ。最後まで行ったら先頭に戻る）→ 🔂 **1曲**（くり返す）→
🔀 **ランダム**（毎回ばらばらに選ぶ。いまと同じ曲は選ばない）と回る。
ランダム中の ⏭ は次をランダムに選び、⏮ は**聴いた順に**1つ戻る（`SFX.bgm.hist`）。
⏮⏭ は「1曲くり返し」でも押せば曲が変わる。音量は 0.42 固定（効果音を消さないため）。

GitHub Pages へは `.github/workflows` の `cp -r bgm _site/bgm` で一緒に載せている。

囲碁＝碁石／オセロ＝ディスク。成駒は赤文字。

### 駒の字の大きさ

**1マスの大きさから決める。** 盤に `--cell`（＝`min(92vw,410px) / 列数`）を持たせ、
駒の字はすべてその比で指定する（1字 .40／2字 .33／3字以上 .215／2列名 .30／接尾辞 .16）。

以前は `min(4.2vw,18px)` のような固定値と「13路以上は小さく」という切り替えだったので、
**12×12（中将棋）で字がマスに収まらず崩れて**いた。列数から決めるようにして、どの盤でも収まる。

| 盤 | 旧 はみ出す駒 | 現在 |
|---|---|---|
| 本将棋 9×9 | 0 | 0 |
| 中将棋 12×12 | **92（全部）** | **0** |
| 大将棋 15×15 | 0 | 0 |
| 摩訶大大将棋 19×19 | 0 | 0 |
| 大局将棋 36×36 | **804（全部）** | **0** |

### 色の設定（盤の設定 → 色）

**盤／自分の駒／相手の駒／背景**を別々に選べる。
**4つとも同じ色の一覧（18色）を共有する**ので、どの色もどの役にも使える。

    木地 白木 濃い木 白 黒 墨 薄墨 紫 夜 朱 茜 藍 紺 空 翠 深緑 森 若草

1色につき「盤として使うとき」「駒として使うとき」「背景として使うとき」の3組の値を
`PALETTE` に持たせてある。背景はどの色でも文字が読めるよう暗めに寄せてある
（白を背景に選ぶと白い背景ではなく、白系の暗いグレーになる）。

| 役 | 入れる変数 |
|---|---|
| 盤 | `--board` `--board2` `--board-line` `--board-edge` `--grid` |
| 自分の駒 | `--koma-top` `--koma-mid` `--koma-bot` `--koma-edge` `--ink` |
| 相手の駒 | `--foe-top` `--foe-mid` `--foe-bot` `--foe-edge` `--foe-ink` |
| 背景 | `--bg1` `--bg2` `--bg3` |

きほんは 盤＝木地／自分の駒＝木地／相手の駒＝紫／背景＝夜。選択欄では
その役のきほんの色に「（きほん）」が付く。中身は CSS 変数の差し替えだけで、
対局の内容にも保存データにも影響しない。選んだ色は `localStorage` の `shogiTheme` に覚える。
古い保存に入っていた名前（`aka` `hinoki` など）は `THEME_ALIAS` で今の名前に読み替える。

## 11. 主要な関数

| 関数 | 役割 |
|---|---|
| `moves(b,r,c)` | レイヤー `b` 上の (r,c) の駒の着手先。`[tr,tc]`、層をまたぐ手は `[tr,tc,1]`。中身は `movesInner`、外側で「×の中の交点の駒はふつうのマスへ出られない」を掛ける |
| `genMoves(b,p,cy,ce)` | 2層＋持ち駒＋パスを合わせた着手一覧。交点の手は `pt:true`、行き先の層は `toPt` |
| `isLegalMove(m,p,b)` | 人間・CPU共通の合法判定（千日手回避・王不見王・ビッチャングンを含む） |
| `simulate(b,m,p,cy,ce)` | 読み用に2層コピーして着手（駒は共有し、行の配列だけ複製） |
| `evaluate(b,cy,ce)` | 局面の点数（相手視点で大きいほど良い） |
| `search(...)` / `cpuPickMove(side,depth)` | αβ探索／最善手選び（反復深化・持ち時間つき） |
| `hashPos(b,cy,ce,side)` | 局面を53bitのキーにする（置換表用） |
| `applyMoveSilent(side,m)` | 実盤への唯一の着手経路。最後に royal の有無で勝敗判定 |
| `LR(b)` / `LC(b)` | レイヤーごとの盤の広さ |
| `ptDiagDirs(R,C)` / `isPalacePoint(R,C)` | 交点から見た宮の判定 |
| `isPalaceCell(r,c)` | マスから見た宮の判定 |
| `isSurrounded(isPt,r,c,cells,pts,ok)` | 囲みの判定（同じ層の4方／別の層の4点） |
| `crossLayerMoves(...)` / `crossJumpPoints(...)` | 層をまたぐ移動／通り道で取れる相手レイヤーの点（飛び越え。`crossCap` では斜め1歩・走りも） |
| `crossLayerOn(b,r,c)` / `atCrossCell(b,r,c)` / `stuckOnCross(b,r,c,t)` | 層を行き来できるか／×の中に居るか／×の中の交点の駒か |
| `diagBlocked(b,r,c,dr,dc,p)` | 斜めの通り道が相手レイヤーの駒に塞がれるか（`crossCap` なら相手の駒は取って通る） |
| `hasRoyalOnBoard(p)` / `countRoyalsOnBoard(p)` | 勝敗判定用（盤上だけを見る）／盤上に残る royal の枚数 |
| `royalDecides()` / `anyRoyalEnds()` | 王の有無で終局するか／王を1枚でも取った時点で終わるか |
| `stateJSON()` / `loadState(text)` | 保存・復元 |

## 12. CPU の改良を外に依頼する

`docs/cpu-extract.md` に、CPU 探索まわりのコードだけを切り出してある。
外部（ChatGPT 等）に改良を頼むときはこのファイルをそのまま渡せばよい。中身は:

- 壊してはいけない前提（人間とCPUで機構を変えない／勝敗ルール／2層・宮・オセロ・囲碁）
- 使ってよい既存APIと、盤・手・RULES の形
- 現状のコード（SPEEDS / evaluate / simulate / genMoves / search / cpuPickMove ほか）
- まだ入っていないもの（静止探索、評価の差分更新、make/unmake ほか）

※ killer/history/counter・Zobrist+置換表・ルートの窓の絞り・持ち時間での打ち切りは
**すでに本体へ入っている**（8.1節）。渡す前に `docs/cpu-extract.md` のコードを
本体の最新版で取り直すこと。
- 直したコードの戻し方と受け入れ条件
